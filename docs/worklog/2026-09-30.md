- 운영 보고(08:17): 체결쏴 주식에서 삼성은 수치가 나오는데 하이닉스(콤보 KRX)는 '적'을 눌러도 "-".
- 원인: 주식 화면은 콤보에서 고른 거래소 시세만 본다(2026-09-17 규칙). 운영 코어 로그 08:00~08:17 분당 통계에

  US3 = NS3, UH1 = NH1 건수가 같은 것도 통합 시세가 NXT 한 곳 거래로만 이루어져서(정상). **고장 아님.**

  안내" — `CSPAT00600` `MbrNo`는 NXT 주문 시 "NXT", 그 외 입력값은 KRX 처리, "스마트 주문은 제공하고 있지
  않습니다". 이후 2026-09-21까지 공지 35건에 SOR·MbrNo 변경 없음. 설치 폴더 Res(`CSPAT00600.res`)의 MbrNo는
  char 3, 허용 값 설명은 없음. (공지 게시판은 EUC-KR — 웹 요약 도구가 제목을 틀리게 읽어 직접 내려받아 확인.)
- 경과: 사용자 결정으로 "시세는 통합, 주문만 콤보"를 구현(831 green)했다가 **같은 날 원복** — 사용자: 주문이 SOR을
  제공하지 않는 한 시세도 거래소 콤보에 맞춰야 한다. 코드·테스트는 커밋 `b03aebb` 상태 그대로.

## 2. HL 주문 연속 전송 (사용자, exec 결정 51)
- 계기(사용자): 같은 조건을 둔 두 세트의 주문가가 다를 때가 있다 — 지연 처리 때문 아닌가.
- 확인 ① 가격 차이: 운영 09-29 하이닉스 HL선 1·2세트가 **같은 밀리초**(11:33:22.213)에 다른 값을 계산(진입
  1304.2 / 1304.8, 청산 1301.3 / 1301.8). 차이가 하루 내내 0.5~0.6으로 일정 → 약 0.04%p. HL선 가격식에서 세트마다
  다른 값은 기준값뿐이라 설정 차이로 판단. **설정값은 코어 로그에 없어 미확인**(운영 자동M 로그 "통과" 줄로 확인 가능).
- 확인 ② 전송 줄 서기: 판정은 0.1초 한 바퀴에 전 세트를 같이 하지만, HL 전송은 앞 요청의 응답까지 기다렸다
  (09-10 nonce 겹침 대책). 왕복 약 0.5초(HL 문서: 취소·ALO 전체 지연 약 380ms — API 서버·대기열·확정 2블록) →
  네 건이 줄 서면 마지막은 약 1.5초 늦고, 판정 순간 가격으로 나가 접수 직후 "역산가 변경" 취소가 반복.
- 조치(사용자: 묶음 전송 말고 연속 전송 — 1세트가 조금이라도 먼저 나가게): `hl_live.NonceClock`(겹치지 않는 번호,
  스레드 안전) + `install_nonce_clock`(SDK `hyperliquid.exchange.get_timestamp_ms` 자리에 끼움, SDK 0.24.0·
  .venv32 동일 확인). 발급기가 붙으면 응답을 기다리지 않고 바로 전송, 못 붙이면 경고 뒤 옛 방식. nonce 거부 2회
  재전송은 그대로. LS(xing) 주문 줄은 손대지 않음.
