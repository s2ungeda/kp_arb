# 작업내역 2026-09-23

## 1. HL선 시험 후속(운영 첫 시험 반영)
- 기준수량 칸 시작값 0→1(0인 채 '적'이면 코어가 수치를 숨김 — 주식·HL선 첫 사용에서 실증).
- 모니터: S괴리(-HP/+S) 표시, 역방향 3칸 표시, HL 호가를 진입 매도1·청산 매수1로 정정(주식선물 화면과 같은
  관례 — 처음 매수1로 잡아 HL 스프레드가 한 번 더 빠졌음). 두 화면 값 차이 = SF 1틱 − HL 스프레드(≈0.04%)로
  진입·청산 둘 다 HL선이 불리 — 스프레드만 보면 LS 메이커(기존)가 유리, HL선은 밀림이 클 때만(사용자 문답).
- 취소·재발주가 격자(0.01)마다 나던 것 → **주문단위 = 화면 호가단위 콤보 값**(매도 올림·매수 내림), 발주범위
  1틱도 그 단위. 세트설정 주문단위·시작호가는 HL선에서 무시.
- S괴리 필터는 HL선에서 두지 않기로(사용자, 시험 동안).
- ALO 겹침 거부 문구 실측·코어 거부 통보 오판(2줄·알람) 수정은 09-22 커밋에 포함.

## 2. LS를 xingAPI로 전부 교체 — 결정·스펙 (DESIGN-ls-xing.md, DESIGN §5.12)
- 이유: REST 발주 왕복 중앙 286ms·p90 1.4초 → HL선(LS 테이커)에 부적합.
- xingAPI = 32비트 COM. 처음 브리지 프로세스+소켓 안 → 사용자 "소켓은 느리다"/"HL SDK 필수인가" 문답 →
  **`ckzg`(이더리움 블롭용 C 확장, HL 서명 무관)만 `eth-account<0.11`로 피하면 코어 전체가 32비트에서 돎**을
  실측(서명이 64비트와 동일, 783 테스트 통과) → **코어 32비트 + COM 코어 안**(브리지·소켓 없음)으로 확정.
- 0단계 완료: `.venv32`(Python 3.12.10 x86) 기준으로 `check.sh`·`build_exe.bat` 전환, `pyproject` 고정.
- xingAPI 설치(`C:\meme`, 사용자) → COM 등록(regsvr32, Claude) → DevCenter Res 내려받기(사용자, 하나씩).
- **구현(전부 가짜 COM/세션 테스트, 라이브 없음):** `xing_res.py`(Res 파서), `xing_com.py`(COM STA 스레드
  세션: 로그인·조회 차선/주문 차선·시간 초과·XAReal·이벤트→asyncio), `xing.py`(`XingQueryClient` +
  `XingGateway(LSApiGateway)` — 전송만 교체), `xing_ws.py`(`XingRealClient(LSWebSocketClient)` — run만
  교체, 프레임으로 부모 파서 재사용), `config.py`(`KP_LS_API`, `XingCredentials`, 키 등록 항목 3개),
  `bootstrap_live` 분기, `xing_check.py`(로그인·왕복·실시간 점검 스크립트). `ls_rest.TrRequester` 계약 추가.
- **실측 Res로 확정:** 주식 주문 TR은 xing에서 CSPAT00600/700/800(REST …601/701/801) — 접두 대응표;
  선물 주문 비밀번호 필드 Pwd(REST InptPwd) — 별칭표; 실시간 블록 이름 InBlock/OutBlock, 키 필드
  shcode/ex_shcode/futcode/base_id/jangubun; 선물·원달러 OutBlock엔 futcode뿐 → 프레임에 shcode 동봉.
- 서버 주소 확정: 실서버 `api.ls-sec.co.kr:20001`(DevCenter 로그인 창). `.env`에 KP_XING_HOST 추가.
- 키 등록 창: xing 자격 3줄을 맨 위로, AppKey/AppSecret은 "(OpenAPI 전용)" 표기, "LS 접근" 라디오(openapi/xing,
  keyring KP_LS_API). 모의 서버는 인증서 비번 없이 로그인(`XingCredentials` 모의면 선택). 모든 .bat → `.venv32`
  (ASCII+CRLF), setup.bat은 32비트 파이썬으로 venv 생성.
- **실측(모의 `demo.ls-sec.co.kr:20001`):** 로그인 0.5초, t1102 조회 왕복 **6~8ms**(첫 건 113ms; REST는 수백 ms),
  실시간 UH1 10초 50건. xing 시동 스모크(`bootstrap 5`) 통과 — 잔고·포지션 2건·미체결 0·실시간 254건·HL 마크,
  REST 시동 로그와 건수 일치. CUR 수신은 장중에 재확인.
- 4단계 주문 시도(16:05, 승인): 모의 장 종료(01458)로 거부 — 거부 경로 정상(선물 20ms·주식 61ms), 본문 REST와
  동일. 접수→취소 왕복은 **내일 장중** 재실측(스크래치 `xing_order_probe.py`).
- 다음: 장중 주문 실측 + CUR 수신 확인 → 운영 PC(실서버, 인증서 비번 필요, reg.bat 관리자) → HL선 시험 재개.
